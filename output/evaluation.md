# PrintProof AI — Evaluation (Step 3)

All numbers in this file come from real runs on 2026-10-25. Raw data: `output/evaluation_results.json`
(evaluation) and `output/audit_trail.json` (every AI call). Nothing was estimated.

## 1. Method

1. **Expected results first.** For 13 test cases I wrote the expected status and problem pages of
   every check in `tests/eval_expected.json` (saved 2026-10-25 05:19 UTC), **before** the case PDFs
   existed and before PrintProof ran on them (PDFs generated 05:24 UTC). The file was not edited after
   testing.
2. **Test PDFs.** `tests/evaluation.py` generates each PDF exactly as its design says and saves it in
   `tests/eval_pdfs/`.
3. **Run and compare.** PrintProof (manual mode = Python checks) checked every case. Each of the
   4 checks per case is one decision → 13 × 4 = **52 decisions**, compared with the expected results.
4. **AI mode.** To save Portkey credits, AI mode ran on only 3 of the cases (plus 2 safety tests,
   see `output/safety_review.md`), using plain-English versions of the same rules.

**Definitions**

| Term | Meaning |
|---|---|
| Accuracy | Decisions where the status (Pass / Fail / Needs Review) equals the expected status |
| Exact accuracy | Status **and** problem page numbers both match |
| False positive | Expected Pass, but PrintProof reported Fail or Needs Review (a problem that doesn't exist) |
| Missed problem | Expected Fail or Needs Review, but PrintProof reported Pass |
| Wrong problem type | Fail reported as Needs Review or the other way round |

Requirements: max 5 pages, US Letter, minimum 10 pt text, 1 in margins — except C02 (A4, 20 mm margins).

### Scores

| Metric | Result |
|---|---|
| Accuracy (status) | **52 / 52 = 100%** |
| Exact accuracy (status + pages) | **52 / 52 = 100%** |
| Expected problems (Fail or Needs Review) detected | **14 / 14** |
| Missed problems | **0** |
| False positives (out of 38 checks that should pass) | **0** |

| Documents with the correct overall verdict | **13 / 13** |
| Check time per document (manual mode) | 0.003 – 0.044 s (all 13 cases together: 0.16 s) |

### What this does and does not show

- PrintProof correctly found every problem **that the test cases were designed to contain**, with
  the right pages and no false alarms, and it marked scanned pages as Needs Review instead of guessing.
  C12 is worth noting: OCR software adds invisible text, and PrintProof ignores it (it would otherwise
  measure fonts that nobody can see).
- **Limits of this evaluation (important for the report):**
  - The 13 cases were designed and generated by the same team that built the checker, with PyMuPDF.
    Real files exported from Word, Google Docs, LaTeX or scanners may behave differently. A perfect
    score on our own test set does **not** prove the same accuracy on real documents.
  - 13 documents and 4 kinds of requirements is a small sample.
  - Known blind spots that were **not** tested: text that is part of an image (e.g. a chart pasted
    as a picture) is not measured by the font check; checks such as line spacing, font family,
    color, bleed or resolution do not exist at all.
- A good next test would use real student PDFs (with permission) and a person's manual check as the
  expected result.

## 3. Manual mode vs AI mode

AI mode ran on 3 evaluation cases with plain-English requirements (no repeated requests, so all
calls were Portkey cache **MISS** = real model work):

| Case | Requirements as written | Tools called (arguments chosen by the AI) | AI vs expected | Tokens | Time |
|---|---|---|---|---|---|
| C02 | "A4 paper only, at most five pages, nothing smaller than 10pt, and keep 20 mm margins on every side." | paper A4 · pages 5 · font 10 pt · margins **20 mm** | 4 / 4 correct | 4,395 | 5.3 s |
| C07 | "Letter size, one-inch margins all around, 10 point minimum, 5 page max." | paper US Letter · margins 1 in · font 10 pt · pages 5 | 4 / 4 correct | 4,492 | 4.0 s |
| C10 | "max 5 pages, US Letter paper, minimum 10 pt font, 1 inch margins" | pages 5 · paper US Letter · font 10 pt · margins 1 in | 4 / 4 correct (2 × Needs Review kept) | 4,500 | 5.0 s |

Run ids: `e976db5da5cd`, `4016c1b40bb2`, `20684cd27b8f`. Each run used 2 API calls and 4 tool calls,
and the AI's report matched the measured results every time (the output validator did not have to
reject anything).

Including the 2 safety runs and the Step 2 runs, **every completed AI run reported the same statuses
as the Python checks**. That is expected by design: the AI cannot measure anything itself — it calls
the same Python functions — and a report that disagrees with them is rejected.

### What AI mode actually adds

| | Manual mode | AI mode |
|---|---|---|
| Measurement accuracy | Python checks | **The same** Python checks (no gain, no loss) |
| Input | Toggles and number fields | Requirements pasted as written, e.g. from a syllabus or print-shop email |
| Units and wording | User converts (e.g. 20 mm → 0.787 in) | Understood "20 mm", "one-inch", "Letter size", "five pages"; unit conversion still done in Python |
| Unclear or unsupported rules | Not visible — the user simply can't enter them | Listed instead of guessed. Step 2 run `f4fbaae0c9fb`: "keep it short", "normal margins", "readable fonts" → asked for exact values; "double spaced" → manual check; only "A4" was checked |
| Explanations | Measurements and details | Plain-English explanation per check and a short summary |
| Cost per document | Free, 0.003–0.044 s | About 4,400–4,700 tokens (2 API calls), about 4–5 s, needs internet and a Portkey key |

**Conclusion:** the AI does not make PrintProof more accurate; it makes it easier to use with
requirements written in normal language and more honest about what was *not* checked. The checking
itself stays in deterministic Python code.
